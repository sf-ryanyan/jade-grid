## 🧭 这是什么

**Jade Grid（玉格）** 是一个 Claude 技能（skill），让 Claude 在做网页时像一位资深设计师一样思考：

> 先判断页面类型 → 出一份简短的设计方案 → 你确认 → 按方案做出高端、好用的网页

名字的意思：

- **Jade（玉）**：温润、高雅、有质感 —— 代表**创意和高级感**
- **Grid（格）**：秩序、严谨、好用 —— 代表**设计规范和可用性**

它最大的特点是**按页面类型平衡这两者**：品牌首页可以大胆、有冲击力；报修表单、后台系统则以清晰好用为先。同一个网站的不同页面，用同一套设计系统，看起来是一个整体。

适合：想用 Claude 做官网、落地页、表单页、后台看板、App 界面的个人、设计师、开发者和小企业。

## 🎯 解决哪些痛点

| 痛点 | 没有它 | 有了它 |
|---|---|---|
| **AI 做的网站千篇一律** | 同样的渐变、同样的卡片、同样的字体，一看就是 AI 做的 | 22 种风格可选，每个项目一个明确风格，避免重复 |
| **配色廉价** | 颜色多而乱，或者灰扑扑没有质感 | 色轮选色 + OKLCH 色彩空间 + 高端配色公式 + 60-30-10 比例 |
| **中文排版乱** | 中文字体丑、中英文挤在一起、标点跑到行首、行距太紧 | 开源中文字体搭配、中英混排、标点与换行、行距字号全部有规则 |
| **国内打不开或很慢** | 用了 Google 字体、地图、验证码，大陆访客等半天 | 访客在大陆时自动避开这些服务，改用本地托管和替代方案 |
| **表单页太花哨** | 报名、报修页面也加一堆动画，反而不好填 | 任务型页面以规范为先：清晰步骤、明确报错、少量动效 |
| **后台系统不好用** | 导航乱、状态缺失、数据看不清 | 系统型页面套用完整标准：导航、空状态、加载、报错、图表 |
| **表单被刷垃圾信息** | 没有防护，或者用了国内打不开的验证码 | honeypot、最短填写时间、频率限制、服务器端校验 |
| **手机上显示错乱** | 只做了电脑版，手机上溢出、按钮太小 | 电脑、平板、手机分别设计，检查 1440 / 768 / 390 三种宽度 |
| **文案空洞** | "赋能""一站式""打造极致体验" | 禁用套话，用大白话说清楚产品做什么 |
| **编造内容** | AI 自己编评价、编数据、编客户 logo | 明确禁止编造评价、数据和案例 |

## ⚙️ 怎么运作

### 1. 先出设计方案，再动工

Claude 不会一上来就写代码。它会先给你一份 5–10 行的**设计方案**：页面类型、访客是谁、选哪种风格、配色、页面结构、动效。你确认或修改后，它才开始做。

想快一点？直接说**"直接做"**，它会把方案浓缩成 3–5 行放在最前面，然后马上开始。

### 2. 4 种页面模式

| 模式 | 典型页面 | 创意 : 规范 | 原则 |
|---|---|---|---|
| **1 展示型** | 品牌首页、作品集、摄影、课程介绍 | 8 : 2 | 风格和创意优先，规范兜底 |
| **2 转化型** | 落地页、产品页、报名页、报价页 | 6 : 4 | 有设计感，但结构遵循成熟的转化逻辑 |
| **3 任务型** | 报修、预约、申请、结账、登录、联系表单 | 3 : 7 | 规范优先：清晰、少步骤、少动效 |
| **4 系统型** | 后台、看板、CRM、订货系统、App | 2 : 8 | 导航、数据、状态、图表标准优先 |

### 3. 分阶段读取，只读需要的内容

主文件（`SKILL.md`）是一张分流表。讨论方案、正式制作、修改、小修，每个阶段只打开需要的参考文件。改一行文字不会读整套风格库。

### 4. 交付格式固定

每次交付包括：代码文件 + 一行总结（模式、风格、调节旋钮、特效、创意点）+ 每张图片的英文 AI 生图提示词。

## ✨ 功能一览

### 🎨 22 种风格库（6 组）

| 组 | 风格 | 适合 |
|---|---|---|
| **L 高端精致** | 编辑奢华、空灵玻璃、柔和结构、杂志网格、液态玻璃 | 地产、生活方式、AI、科技产品、课程 |
| **M 极简理性** | 极简文档、瑞士现代、夸张极简、纸质阅读 | SaaS、工具、专业服务、建筑、文档 |
| **B 大胆表现** | 工业印刷、新粗野主义、动态文字、包豪斯、孟菲斯 | 健身、工程、年轻品牌、活动、教育 |
| **T 科技未来** | 战术终端、极光渐变、AI 原生界面 | 数据、AI 工具、金融科技 |
| **N 自然温暖** | 自然有机、复古胶片、黏土风 | 健康、茶饮、餐饮、摄影、游戏 |
| **S 系统界面** | 数据看板、企业门户 | 后台、CRM、客户门户 |

每种风格都有完整的配色、字体、组件、动效和禁用项。

### 🌈 配色体系

1. **色相**：用色轮选配色方案（互补色、邻近色、三角配色），在 OKLCH 色彩空间里计算
2. **性格**：淡雅、柔和、深沉、鲜艳、暗色，五选一
3. **高端公式**：大面积带色调的中性色 + 低彩度主色 + 唯一一个鲜艳的强调色
4. **比例**：60% 主色调 · 30% 辅助色 · 10% 强调色
5. **检查**：对比度达标 + 灰度检查（黑白下层次依然清楚）

### 🧰 创意工具箱（展示型和转化型）

- 8 种落地页策略、10 种首屏（Hero）类型
- 20 多种版块和组件（无缝便当格、粘性卡片堆叠、前后对比滑块、时间线等）
- 9 种滚动特效，每个网站选 2–3 种
- **"一个创意 + 一个可互动的东西"**：每个网站找一个只属于这个主题的创意点，再做一个真正能用的小工具（计算器、选择器、对比滑块等）

### 📐 标准层

无障碍 · 性能 · 触控 · 表单 · 状态 · 导航 · 图表 · 功能性动效 · 设计系统文件 · App 与深色模式。按页面模式自动启用需要的部分。

## 🇨🇳 中文优化

这是 Jade Grid 和其他设计技能最大的不同。

| 方面 | 做法 |
|---|---|
| **中文字体** | 只推荐开源可商用字体：思源黑体 / 思源宋体（Noto Sans SC / Noto Serif SC）、霞鹜文楷、得意黑，并给出搭配方案和系统字体回退 |
| **中英混排** | 中英文之间留空格；中文用全角标点、英文用半角标点；标点不出现在行首 |
| **字号行距** | 正文 16–18px（手机不小于 16px）；中文行距 1.7–2.0；中文每行约 25–40 字 |
| **标题** | 中文标题行距更紧、字重更重；短词不拆行；电脑不超过 2 行，手机不超过 3 行 |
| **强调** | 中文不用假斜体，用字重、颜色、下划线或着重号 |
| **加载速度** | 中文字体文件很大：按需切片或子集化，不预加载整个中文字体 |
| **大陆访问** | 访客在中国大陆时，避开 Google 字体、地图、YouTube、reCAPTCHA 和部分国外 CDN，改用本地托管和替代方案 |
| **文案** | 禁用"赋能、一站式、全方位、打造、引领、极致、颠覆"等套话 |
| **本地化格式** | 日期、万 / 亿、货币符号、电话格式按目标市场处理 |
| **简繁** | 正确设置 `lang`（简体 zh-CN，繁体 zh-Hant / zh-TW / zh-HK），双语页面分段标注 |
| **交流语言** | 你用中文提问，设计方案和交付说明就用中文 |

## 🚀 快速开始

### 第 1 步 —— 安装

**在 Claude 网页版 / 桌面版：**

1. 打开 [Releases 下载页](https://github.com/sf-ryanyan/jade-grid/releases/latest)，下载 **`jade-grid.zip`**。**不要解压。**
2. 在 Claude 里打开 **Customize → Skills → Upload**，选择这个 zip。
3. 确认技能已开启，名字显示为 **jade-grid**。
4. 升级时，用同样方法上传新版本 zip，替换旧版本。

> 💡 请从 Releases 下载，不要用 GitHub 页面上的"Code → Download ZIP"。那个压缩包会多一层文件夹，上传到 Claude 可能出错。

**在 Claude Code：** 把解压后的 `jade-grid` 文件夹放到 `~/.claude/skills/`（所有项目可用）或项目里的 `.claude/skills/`（只在该项目可用）。

### 第 2 步 —— 试一个示例

打开 [examples/README.md](examples/README.md)，复制任意一段示例发给 Claude，例如：

```
帮我做一个茶叶品牌的官网首页，中文为主。
品牌：山间茶事（虚构），主打高山乌龙。
访客主要在中国大陆。
```

Claude 会先给你设计方案，确认后开始制作。

## 💬 日常怎么用

直接说你要做什么，不需要提技能的名字。

| 你想… | 可以这样说 | 你会得到 |
|---|---|---|
| 做一个新网站 | "帮我做一个 [行业] 的官网" | 设计方案 → 确认后的完整网页 |
| 跳过方案直接做 | "做一个 [页面]，直接做" | 3–5 行方案 + 网页 |
| 做落地页 | "做一个 [产品] 的报名落地页" | 有转化逻辑的落地页 |
| 做表单页 | "做一个预约 / 报修 / 申请页面" | 清晰好填、带防刷和隐私提示的表单 |
| 做后台 | "做一个 [业务] 的管理看板" | 带导航、状态、图表的后台界面 |
| 改版 | "这是我的网站，帮我改得更高端"（上传文件） | 新版本文件，原文件不动 |
| 小修改 | "把按钮颜色改深一点" / "改一下这段文字" | 只改要求的地方 |
| 换风格 | "换一种风格看看" | 新风格的方案和版本 |

**几个小技巧：**

- **说清楚访客在哪里**（中国大陆 / 海外华人 / 国际），这会影响字体和第三方服务的选择。
- **说清楚语言**：只要中文、只要英文，还是中英双语切换。
- **图片自己生成**：Claude 会留好图片位置，并给你每张图的英文 AI 生图提示词。
- **改版不会覆盖原文件**：每次都生成新版本（例如 `index-v2.html`）。

## 💡 省 token 的设计

重复的小修改尽量省，正式制作才完整读取。**省 token 的前提是不降低设计效果。**

| 任务 | 读取的技能内容（约） |
|---|---|
| 小修改（文字、颜色） | 约 4,800 tokens |
| 讨论设计方案 | 约 6,500–7,000 tokens |
| 制作展示型 / 转化型页面 | 约 8,500–9,500 tokens |
| 制作任务型 / 系统型页面 | 约 8,000–9,000 tokens |

> 以上为估算值，实际会因请求长短和上传的文件不同而变化。全部参考文件一次性读取约 11,700 tokens。

**小建议**

- **一个页面开一个对话**，对话越长，每一轮重复发送的内容越多。
- 只上传这次需要的文件。
- 这份 README **不会**在技能运行时被读取，不花 token。

## 🚧 限制

- **只生成代码，不负责上线。** 部署到服务器、GitHub Pages 或其他平台需要你自己操作。
- **不生成图片。** 只留好图片位置并提供英文生图提示词。
- **AI 生成的代码需要检查。** 上线前请在电脑和手机上测试，确认内容、链接和表单都正常。
- **表单后端需要你自己配置**（例如表单服务或服务器函数），技能会给出安全建议和代码。
- 无障碍、隐私等规则是通用建议，**不等于符合任何法律法规**。
- 网络环境会变化，关于中国大陆访问的建议请以实际测试为准。
